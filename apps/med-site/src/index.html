One window for the whole review. From the agent's explanation to the pushed commit.

01

Read the explanation

The agent explains its work in a brief. Each sentence cites the lines it changed, and each citation opens as a short diff below it.

  • Diagrams, tables, and images in place
  • Changed files the brief does not mention
  • Comment on a passage of the brief

02

Comment on the diff

Commits and working changes read as one continuous diff, split or unified. Comment on a line or a range without leaving the keyboard.

  • Blame for the line at the cursor
  • Find any file, code, or symbol
  • Vim keys in the editor

03

Work with your agents

The agent's session streams beside the review: its replies, tool calls, plan, and background work. Send your comments from its message box, and the next round becomes a new iteration of the same review.

  • Start an agent from a saved review
  • See which agent is waiting for you
  • Allow or deny each request

04

Commit, push, and follow the pull request

Stage files, write the message, commit, and push from the Commit tab. Paste a pull request link to open it as a workspace, with its GitHub comments beside the diff.

  • Med never force-pushes
  • Codex review findings as comments
  • GitHub through your own gh sign-in

05

Keep your notes beside the code

Add an Obsidian vault next to your repositories. Follow wiki links and backlinks, and edit in Vim with a live preview.

  • Markdown, math, and Mermaid
  • Image embeds with sizes
  • Your .obsidian settings stay as they are

  • Runs on your machine

    One executable with the UI and offline docs. No account and no cloud.

  • Keyboard first

    c comments on the line, q opens the Commit tab, and ⌘K finds every command.

  • Open source

    MIT licensed. Saved reviews keep their code and comments across restarts.
